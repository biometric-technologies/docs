Biometric SDK

An open-source library that recognizes people by their iris or their face, and runs on Android, iOS and the JVM from one Kotlin code base. You give it an eye image or a selfie; it gives you a compact template and a yes-or-no answer to "is this the same person?". Nothing leaves the device or your server: there is no cloud call anywhere in the code.

Iriscan uses the same code in its own products, and the face match of this SDK is the one that runs inside Inji Wallet, the reference wallet of MOSIP, the open-source national ID platform.

What it does

  • Turns a near-infrared photo of an eye into an iris template and compares two templates. The whole iris pipeline is plain Kotlin, so it behaves the same on every platform and needs no native libraries.
  • Finds a face in a photo, turns it into an embedding with a FaceNet-type model and compares embeddings. Uses ML Kit on Android, Apple Vision on iOS and OpenCV on the JVM to find the face, and TensorFlow Lite to run the model.
  • Checks that a face is live, not a printed photo or a screen, with a liveness model, and tells which way the head is turned.
  • Reads and writes PNG and BMP images and converts to and from Bitmap, UIImage and BufferedImage.
  • Serializes templates as ISO/IEC 19794-6 (iris image) and ISO/IEC 19794-2 (finger minutiae) records, the formats other biometric systems understand.

Quick start

Add the dependency. Replace 0.7.0 with the latest version shown in the badges.

// Android
implementation("net.iriscan:biometric-sdk-android:0.7.0")

// JVM
implementation("net.iriscan:biometric-sdk-jvm:0.7.0")

# iOS, Podfile
pod 'BiometricSdk', '~> 0.7.0'

Configure once, then compare two eye images:

import net.iriscan.sdk.BiometricSdkFactory
import net.iriscan.sdk.iris.*

val config = BiometricSdkFactory.configBuilder()
    .withContext(applicationContext)                 // Android only
    .withIris(
        extractor = IrisExtractProperties(),
        encoder = IrisEncodeProperties(),
        matcher = IrisMatchProperties(threshold = 0.67),
    )
    .build()
BiometricSdkFactory.initialize(config)
val sdk = BiometricSdkFactory.getInstance()!!

val eye1 = sdk.io().readImage(bytesOfFirstPhoto)
val eye2 = sdk.io().readImage(bytesOfSecondPhoto)

val template1 = sdk.iris().encoder().extractAndEncode(eye1)   // ByteArray, a few kilobytes
val template2 = sdk.iris().encoder().extractAndEncode(eye2)

val samePerson = sdk.iris().matcher().matches(template1, template2)

Store template1 instead of the photo: it is what you compare against next time, and the photo cannot be rebuilt from it.

Face comparison works the same way, with the model file supplied by you:

import net.iriscan.sdk.face.*

val config = BiometricSdkFactory.configBuilder()
    .withContext(applicationContext)
    .withFace(
        extractor = FaceExtractProperties(),
        encoder = FaceEncodeProperties(
            FaceNetModelConfiguration(
                path = "https://example.com/models/facenet.tflite",  // URL or local file
                inputWidth = 160, inputHeight = 160, outputLength = 128,
                modelChecksum = null, modelChecksumMethod = null, overrideCacheOnWrongChecksum = null,
            )
        ),
        matcher = FaceMatchProperties(threshold = 1.0),
        liveness = null,
    )
    .build()
BiometricSdkFactory.initialize(config)
val sdk = BiometricSdkFactory.getInstance()!!

val face1 = sdk.face().encoder().extractAndEncode(nativeImage1)   // Bitmap, UIImage or BufferedImage
val face2 = sdk.face().encoder().extractAndEncode(nativeImage2)
val samePerson = face1 != null && face2 != null && sdk.face().matcher().matches(face1, face2)

Models are downloaded once and cached on the device. Working example apps: Android, iOS and React Native.

How it works

Iris. The iris is the colored ring around the pupil. Its texture is formed before birth, does not change with age and differs even between identical twins and between a person's two eyes, which is why it is the most accurate biometric in everyday use. The SDK finds the pupil and the outer edge of the iris in the image, masks out eyelids and reflections, unwraps the ring into a rectangular strip and turns the texture of the strip into a string of bits, the iris code (with log-Gabor filters, the classic iris-code method; releases up to 0.6.0 compared neighboring pixels into local binary patterns). Two codes are compared by counting the bits that differ, ignoring masked areas; the SDK reports a similarity between 0 and 1 and calls it a match above the threshold you configured. Iris cameras use near-infrared light, which makes the texture visible even in dark eyes, so the algorithm expects NIR images.

The pictures above are real output of the iris pipeline on the iris photo from our blog and on a near-infrared eye photo by Boodlemason (Wikimedia Commons, CC BY-SA 3.0); the figure files are under the same license.

Face. The platform's face detector finds the largest face and its eyes, the SDK crops and aligns it, and a FaceNet-type neural network turns the crop into a list of numbers called an embedding. Faces of the same person give embeddings that are close together; the matcher measures the distance and compares it with the threshold. The network is a TensorFlow Lite file that you choose and host, so you can replace it with a better one without touching the SDK. The liveness check runs a second model on the face crop and returns a score; the position check uses the detector's head angles.

Templates, not photos. A template is small, cannot be turned back into the image, and is what you keep in your database. The ISO/IEC 19794 serializers let you exchange records with other vendors' software instead of being locked in.

Every configuration parameter, the iris pipeline step by step and the per-platform notes are in the sections below; integration guides for the cloud and the edge service are on docs.iriscan.com.

Initialization and configuration

The SDK is a process-wide singleton:

  1. BiometricSdkFactory.configBuilder() returns a BiometricSdkConfigBuilder.
  2. withContext(...), withIris(...) and withFace(...) select what to initialize; build() returns a BiometricSdkConfig.
  3. BiometricSdkFactory.initialize(config) creates the operations. Only the first call has an effect: later calls return without changing the configuration.
  4. BiometricSdkFactory.getInstance() returns BiometricSdkOperations, or null (and logs an error) before initialization.

BiometricSdkOperations exposes io(), iris(), face() and qualityControl(). iris() and face() throw IllegalStateException when the modality was not configured, and each face sub-operation throws the same exception when its own properties were not given. io() is always available.

initialize creates the TensorFlow Lite interpreters of the configured face operations immediately, which loads (and, for https: paths, downloads) the model files. Downloads run synchronously on the calling thread, so on Android call initialize off the main thread when models come from the network.

Points specific to Swift:

  • Kotlin default argument values are not exported to Objective-C and Swift. Every argument of withFace, withIris and of the property constructors has to be passed. This is easy for the face classes but verbose for the iris property classes (for example IrisExtractProperties takes a Kotlin array of ClosedRange values).
  • Kotlin methods that are overloaded on the parameter type, such as IrisEncoder.extractAndEncode(sample:) for Image and BiometricRecord, get disambiguated names in the generated Objective-C header. Check BiometricSdk.h in the framework for the exact Swift names.
  • Kotlin exceptions are only translated into Swift errors for functions annotated with @Throws, which here is initialize. Calling iris() or face() on an SDK that was not configured for that modality terminates the app.

The overloads that take a BiometricRecord (extract, encode, extractAndEncode, matches, matchesAny) are declared but not implemented and throw NotImplementedError.

The input is an Image of any color type: RGB is converted with ITU-R BT.601 luma, BINARY maps to 0 and 255. The input is never modified. The algorithm is tuned for near-infrared eye images as produced by iris cameras; the eyelid detector, for example, assumes that eyelid skin is brighter than the iris.

The iris code keeps no shared mutable state, so the iris operations can be called from several threads.

1. Preparation and reflection removal

Segmentation runs on a copy downscaled by area averaging so that the shorter side is about workingSize pixels (240 by default; images are never upscaled). Specular reflections create strong false edges, so they are removed first. A pixel is a reflection if it is saturated (at least the larger of 230 and the 99.5th percentile of the image) or if it belongs to a compact bright spot: brighter than 170 and more than 40 grey levels above a Gaussian-smoothed background, in a connected component whose bounding box is smaller than max(6, shortSide / 20) pixels. The size limit keeps bright sclera along the limbus and bright iris texture out of the mask. The mask is dilated by 3 pixels and the masked pixels are filled layer by layer from the 25th percentile of their unmasked 7 x 7 neighbourhood, so the halo of a glint does not spread into the fill. The result is smoothed with a Gaussian (sigma 1.2) for the boundary searches.

2. Pupil

Candidate pupils come from dark regions: starting from the darkest pixels below the image median, regions are grown while pixels stay within max(12, 0.3 * (median - seed)) of the seed value. Regions of plausible size give up to 8 candidates, each represented by its centroid and equivalent radius, which places the search near the true centre even when the darkest pixel is off-centre.

Around each candidate the boundary is searched with Daugman's integro-differential operator: for each centre and radius, the mean intensity on the circle is sampled in 64 directions grouped into 8 angular sectors, the radial derivative is computed per sector and smoothed with a [1 2 1] kernel, and the sectors are combined by the 0.375 quantile instead of the mean. A boundary therefore has to be present in about five of the eight sectors, which rejects circles that only touch a strong partial edge such as an eyelid or a cluster of eyelashes. Candidates are ranked by edge strength multiplied by the darkness of the disc inside. The best circle is refined on a half-pixel grid.

Illuminators often leave a ring of glints inside the pupil, which produces a circular edge smaller than the pupil. The SDK therefore looks for a larger concentric edge; if the ring between the two circles is as dark as the pupil, the larger circle is taken.

Pupil radius limits default to 3% to 22% of the shorter image side and can be set in pixels with minPupilRadius and maxPupilRadius.

3. Limbus (iris boundary)

The iris boundary is searched as a separate circle, so pupil and iris centres may differ. Only the angular sectors in irisAnglesToSearch are used (by default -40 to 40 degrees and 140 to 220 degrees, with 0 pointing right and 90 down), because eyelids rarely cover the left and right sides of the iris. The search radius is limited by minIrisRadius and maxIrisRadius (12% to 60% of the shorter side by default) and by the allowed pupil-to-iris ratio (minPupilIrisRatio 0.15, maxPupilIrisRatio 0.75).

The search has two stages, because searching all centres at once lets eyelid and eye corner edges win:

  1. Centres within 2 pixels of the pupil centre are tried with a radial derivative taken over a wider scale, which measures the total step of the blurred limbus rather than iris texture. The four lateral sectors are combined by the 0.34 quantile, so both sides of the eye must show the edge, and at least 75% of the sectors must lie inside the image. The innermost local maximum that reaches 90% of the strongest edge is taken, since eyelids and eye corners lie further out. If nothing is found, the search is repeated with the 0.67 quantile, which accepts an edge visible in two of the four sectors.
  2. Centre and radius are refined around that result: up to 12% of the radius horizontally but only 4% vertically, since lateral arcs fix the horizontal position well and the vertical one only weakly, and within 10% of the radius.

A pair is rejected when the pupil circle is not inside the iris circle.

4. Eyelids

When detectEyelids is true, upper and lower eyelids are located separately. The central 1.5 iris radii of the iris width are split into three vertical bands. In each band, mean intensities of the iris rows (between pupil and limbus) are compared above and below every row, and the eyelid is the row with the strongest step from bright skin to darker iris. A step is accepted only if it is at least max(15, 0.2 * iris intensity) grey levels and the skin side is brighter than the typical iris intensity, measured as the median of the lateral iris sectors, by at least max(15, 1.5 * robust sigma). Three points define a parabola, which must be convex towards the pupil; otherwise the most occluding point gives a horizontal line. The upper eyelid is searched down to the pupil centre, since it can cover part of the pupil.

5. Normalization

The iris is unwrapped with Daugman's rubber-sheet model to a normalizedWidth x normalizedHeight texture (256 x 64 by default) by bilinear sampling of the full-resolution grayscale image. Each column is an angle, starting at 0 degrees (to the right in image coordinates); each row interpolates linearly between the point on the pupil circle and the point on the limbus circle at that angle, which handles non-concentric circles and pupil dilation. The radial coordinate runs from 4% to 96% of the way out, to stay clear of the blurred boundaries.

A sample is marked invalid when it lies outside the image, on a reflection (mask recomputed at full resolution), above the upper eyelid or below the lower eyelid. Finally, samples further than outlierSigma (3.0) robust standard deviations from the median intensity of the lateral sectors are masked, which removes eyelashes (darker) and residual skin or glints (brighter). The lateral statistics keep a large occluded area from shifting the reference. If less than 20% of the texture remains valid, extraction returns null.

extractor().extract(image) returns this texture as a GRAY image in which invalid pixels are -1.

6. Encoding

The texture is averaged into templateRows radial bands (16 by default, 4 texture rows each). A column of a band is valid if at least half of its rows are valid; a band with fewer than a quarter valid columns stays fully masked. Each band is a periodic signal around the eye. Its mean is removed and it is filtered in the frequency domain (radix-2 FFT, so the texture width must be a power of two) with a one-sided 1D log-Gabor filter:

G(f) = exp( -ln(f / f0)^2 / (2 * ln(sigmaOnF)^2) ),   f0 = 1 / wavelength,   G = 0 for f <= 0

With the defaults wavelength = 18 texture pixels and sigmaOnF = 0.5. Because the filter has no DC response, the code does not depend on image brightness or contrast. Keeping only positive frequencies yields a complex response whose phase is quantized to two bits, the signs of the real and imaginary parts, at templateCols angular positions (128 by default, every second texture column).

The mask bit of a cell is set only if the centre column is valid and at least three quarters of the filter window (half a wavelength on each side) saw valid iris. Fragile bits, the responses closest to zero, flip easily between captures; the weakest fragileBitFraction (15%) of the real and of the imaginary responses among valid cells are masked as well.

7. Template format (IR2)

Offset Size Content
0 3 ASCII IR2
3 1 Version, currently 1
4 1 Rows (templateRows)
5 1 Columns / 32
6 1 Bits per cell, always 2
7 1 Reserved, 0
8 rows x cols x 2 / 8 Code bit plane
... rows x cols x 2 / 8 Mask bit plane

Bit (r * cols + c) * 2 is the sign of the real part for row r and column c, and the next bit the sign of the imaginary part. Bits are packed into 64-bit words stored little-endian; every row occupies whole words, so an eye rotation is a circular shift of each row. With the defaults a template is 16 x 128 x 2 = 4096 code bits plus 4096 mask bits: 8 + 512 + 512 = 1,032 bytes.

8. Matching

Two templates are compared with the masked fractional Hamming distance. The probe is shifted circularly by -maxShift to +maxShift columns (8 by default; one column is 360 / 128 = 2.8 degrees, so about plus or minus 22.5 degrees of head tilt are compensated). For every shift:

n      = popcount(maskA AND maskB)                  bits valid in both templates
HDraw  = popcount((codeA XOR codeB) AND maskA AND maskB) / n
HDnorm = 0.5 - (0.5 - HDraw) * sqrt(n / normalizationBits)

The normalization (Daugman) pulls comparisons that rest on few bits towards 0.5, so a small overlap cannot produce a confident match. normalizationBits defaults to 40% of the template bits (1,638 for the default size). Shifts with fewer than minComparedBitsFraction (15%, 614 bits by default) common bits are ignored. The smallest HDnorm over all shifts gives the score 1 - HDnorm: 1.0 for identical codes, about 0.5 for unrelated irises. If no shift has enough common bits, or the templates have different dimensions, the score is 0.

For 1:N search, identify prepares all rotations of the probe once and scans the gallery linearly; with the defaults each comparison is 17 shifts over 64 words of code and mask. It returns the index and score of the best candidate if the score reaches the threshold.

Templates created by SDK 0.6 and earlier have no IR2 header. Two such templates are still compared with the old byte-equality method and legacyThreshold (0.7), but a legacy template never matches an IR2 template (score 0). To move to the new algorithm, re-enroll from the stored images.

Choosing the threshold

The default threshold 0.67 corresponds to a Hamming distance of 0.33. The right value depends on your sensors, population, capture conditions and the false match rate you can accept, especially for large 1:N galleries, where the chance of a false match grows with the gallery size. Measure score distributions on your own images with the benchmark and set IrisMatchProperties(threshold = ...).

On Android the detector is called synchronously (Tasks.await), so face operations must run off the main thread. The JVM cascades are bundled in the JAR and copied to ${java.io.tmpdir}/.biometric-sdk/ on first use.

Encoding and matching

The encoder resizes the crop to inputWidth x inputHeight (bilinear on Android, area averaging on the JVM, Core Graphics high-quality interpolation on iOS) and standardizes it per image: (x - mean) / max(std, 1 / sqrt(N)) over all pixel values, as FaceNet expects. The model output is outputLength float32 values, returned as 4 * outputLength bytes in big-endian order on all platforms. On iOS, the encode(Image) path converts the SDK image to grey replicated in three channels; the NativeImage path uses RGB on all platforms.

The matcher L2-normalizes both embeddings and returns their Euclidean distance: 0 for identical directions, sqrt(2) for orthogonal ones, 2 for opposite ones. Normalizing in the matcher keeps distances comparable for models without a final L2 layer. Templates of different lengths cause an IllegalArgumentException.

Photo liveness

The photo liveness check is written for a DeePixBiS-type model: the face crop is resized to inputWidth x inputHeight, scaled to [-1, 1] with (x / 255 - 0.5) / 0.5, converted to planar channel-first layout, and the model's 14 x 14 map of live probabilities is averaged. validate returns score > threshold. The extractAndScore and extractAndValidate variants run the platform face extractor first, without alignment.

Position check

detectPosition classifies head orientation against threshold (degrees) using the detector's angles: 1 (left) if yaw >= threshold, 2 (right) if yaw <= -threshold, 3 (top) and 4 (bottom) from the second angle, otherwise 0. On Android the second angle is ML Kit's headEulerAngleZ, which is in-plane rotation; on iOS it is Vision's pitch, which Vision reports from iOS 15 (earlier versions are treated as 0). The JVM implementation always returns 0.

Model loading and caching

Face and liveness models are loaded through ResourceIO, which is initialized by BiometricSdkFactory.initialize. A model path has the form location:path:

Prefix Android iOS JVM Example
assets: APK assets assets:models/facenet.tflite
bundle: Main bundle resource (name and extension) bundle:facenet.tflite
classpath: yes yes classpath:/models/facenet.tflite
file: File in the app's internal files directory (Context.openFileInput) Absolute path Absolute path file:/opt/models/facenet.tflite
https: yes yes yes https://example.com/facenet.tflite

Local paths are read on every initialization. https: resources are downloaded with Ktor and cached under a fixed name per model type, facenet.tflite or liveness-photo.tflite, in the platform cache directory (Context.cacheDir, NSCachesDirectory, ${java.io.tmpdir}/.biometric-sdk/). Once cached, the file is used without contacting the server.

The model configuration classes accept modelChecksum, modelChecksumMethod (HashMethod.SHA256 or HashMethod.CRC32) and overrideCacheOnWrongChecksum. The checksum is compared as text: SHA-256 as lowercase hex; CRC-32 as Kotlin's signed hexadecimal Int.toString(16), kept for compatibility with earlier versions. When all three are set:

  • the downloaded (or locally read) file must match the checksum, otherwise an IOException is thrown;
  • with overrideCacheOnWrongChecksum = true, a cached file with a different checksum is replaced by a fresh download.

Checksums are currently applied only on iOS. On Android and the JVM the interpreter loads the model through a code path that accepts these arguments but does not check them (see Limitations). Because the cache name does not depend on the URL, changing the model URL on Android or the JVM does not replace a cached model; clear the cache file to force a new download.

Images, records and I/O

Image types

Image is the SDK's own raster type, used by the iris pipeline and the common codecs: Image(width, height, colorType, colors), where colors is an IntArray in row-major order. RGB pixels are 0xRRGGBB, GRAY pixels 0 to 255 (-1 marks masked pixels in iris textures), BINARY pixels 0 or 1. NativeImage is the platform image used by the face module (Bitmap, CGImageRef wrapper, BufferedImage).

io() operations

Call Description
readImage(bytes) Decode PNG or BMP in common code (format detected from the signature) into an Image: GRAY for grayscale files, RGB (0xRRGGBB) otherwise
writeImage(image, ImageFormat.PNG / BMP) Encode in common code; JPEG throws UnknownFormatException
readNativeImage(dataBytes) Decode with the platform decoder (any format the platform supports)
writeNativeImage(nativeImage, format) Android: PNG or JPEG (quality 90), BMP not supported. JVM: PNG, JPEG, BMP via ImageIO. iOS: returns the raw 32-bit pixel buffer regardless of format
convert(...), convertTo...(...) Conversion between Image and the platform image, listed in Architecture
readRecord(bytes), writeRecord(record) Record I/O through registered serializers; no serializer is registered yet, so both throw UnknownFormatException

The common PNG decoder reads non-interlaced 8-bit images of every color type (grayscale, grayscale with alpha, RGB, RGB with alpha, palette), all five row filters and image data split across several IDAT chunks, and checks every chunk CRC. Alpha is dropped. It writes RGB images as RGB and GRAY or BINARY images as grayscale. zlib inflate and deflate are implemented in Kotlin, so PNG behaves the same everywhere. 16-bit and interlaced PNGs are rejected with an IOException; for those, and for JPEG or TIFF, decode with the platform (readNativeImage followed by convert).

The BMP codec reads uncompressed 8-bit (palette), 24-bit and 32-bit bitmaps, bottom-up or top-down; an 8-bit bitmap with a gray palette becomes a GRAY image. It writes 24-bit bitmaps.

Accuracy and the benchmark

Running the benchmark

IrisDatasetBenchmark is a JVM test (src/jvmTest) that enrolls every image of a dataset with the default properties, compares all pairs and prints the results. It is skipped unless IRIS_DATASET is set.

IRIS_DATASET=/data/CASIA-Iris-Interval IRIS_REPORT=build/iris-report \
  ./gradlew jvmTest --tests '*IrisDatasetBenchmark*'
Variable Meaning
IRIS_DATASET Directory searched recursively for bmp, jpg, jpeg, png, tif, tiff files
IRIS_SUBJECT Regex with one group that extracts the identity (one eye of one person) from the path relative to IRIS_DATASET. Default: the parent directory, which fits layouts such as CASIA-Iris-Interval 001/L/S1001L01.jpg
IRIS_LIMIT Maximum number of images
IRIS_REPORT Directory for scores.csv (every comparison: subjects, genuine flag, score, compared bits, shift) and det.csv (FMR and FNMR for thresholds 0.40 to 1.00 in steps of 0.005)

The report contains, in the terms of ISO/IEC 19795-1:

  • Failure to enroll: images that could not be read or segmented, or whose usable texture was below 20%. Time per image is printed as well.
  • Genuine and impostor score distributions: mean, standard deviation, minimum and maximum of 1 - HD for pairs of the same eye and of different eyes.
  • EER: the error rate at the threshold where FNMR and FMR are closest (thresholds 0.40 to 1.00, step 0.001), with that threshold.
  • FNMR at fixed FMR: for FMR of 1%, 0.1%, 0.01% and 0.001%, as far as the number of impostor pairs allows, with the threshold that achieves it.
  • FNMR and FMR at the configured default threshold.

To evaluate other settings, change the property objects at the top of the test.

The unit tests in commonTest also check the pipeline on synthetic near-infrared eyes (SyntheticIris): segmentation accuracy, eyelid masking, rotation compensation, invariance to brightness and contrast, template serialization, 1:N identification and separation of genuine and impostor scores. Synthetic data catches regressions but does not measure accuracy.

Limitations and known gaps

Accuracy and standards

  • Thresholds must be calibrated. The iris threshold 0.67 is a starting point checked on one dataset, the quality defaults follow values commonly used with ISO/IEC 29794-6, and face and liveness thresholds depend entirely on the model you supply.
  • Nothing in the SDK is a certified implementation of an ISO/IEC standard. Quality metrics follow the components of ISO/IEC 29794-6, and the record serializers follow the layout of ISO/IEC 19794-6 and 19794-2, without conformance testing.
  • The iris pipeline is tuned for near-infrared images; visible-light iris images have not been evaluated. There is no iris presentation attack detection.
  • 1:N iris identification is an exhaustive linear scan in memory. It has no index, so very large galleries need partitioning or a dedicated service.

Not implemented

  • qualityControl() and the BiometricRecord overloads of the iris API throw NotImplementedError.
  • io().readRecord() and io().writeRecord() have no registered serializers.
  • Fingerprints are limited to the ISO/IEC 19794-2 record format: there is no fingerprint extraction or matching.
  • Position liveness is not implemented on the JVM.

Known issues

  • Model checksums are not verified on Android and the JVM (the data-loading path of ResourceIO ignores them); only iOS checks them.
  • On the JVM, the cache directory ${java.io.tmpdir}/.biometric-sdk/ is created only when a face extractor loads its cascades. With extractor left null in withFace, the encoder or liveness model is loaded before any extractor exists, and saving a downloaded model fails if the directory is missing.
  • writeNativeImage on iOS returns raw pixels instead of an encoded file, and on Android does not support BMP.
  • The common PNG decoder does not read 16-bit or interlaced files.
  • The 19794-6 range field (camera to eye distance) is kept only as "unassigned", "failed" or "measured": a measured distance is read back as RANGE_OVERFLOW.
  • Face extraction differs between platforms (choice of face, crop margin, alignment), so embeddings of the same photo are not guaranteed to be identical across platforms.
  • BiometricSdkFactory.initialize cannot reconfigure an initialized SDK, and debug logging is always installed.

For large-scale 1:N de-duplication, see the iris de-duplication service; for other licensing terms, iriscan.com/get-started.
